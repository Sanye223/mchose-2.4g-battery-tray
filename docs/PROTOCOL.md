# MCHOSE A7 系 HID 协议逆向笔记

> 以下内容全部来自 **MCHOSE A7 Pro**（PAW3395）实机抓包与验证（2026-10）。
> 配置接口：usage page `0xFF01` 的厂商自定义 HID，特征报告通道 65 字节。
> 通用帧规则：`发送 = reportId + XOR0xFF(body)` 并补 `0x00` 至 65 字节（即补齐后为 `FF`）；
> `接收 = 65 字节特征报告`，`payload = XOR0xFF(raw[2:])`，`raw[1]` 应等于 `body[0] ^ 0xFF`（命令字回显校验）。

## 1. 设备枚举

| 场景 | VID:PID |
|---|---|
| 2.4G 接收器 | `5253:1021`、`3837:100A` |
| 有线（含插线充电中） | `5253:0010`、`3837:4018` |

关键坑：**插线充电时鼠标切到有线模式**（换 PID），接收器仍在枚举里但无线链路断开、只回垃圾包。所以候选设备要放宽到「VID 对上就算」，并采用「快扫一遍 → 全失败再深扫」的策略，避免把时间预算耗在死接口上。

接收器另有一个 usage page `0xFF0B`（61B）接口，推测是 MCHOSE M HUB 的配置通道，本项目未使用。

## 2. 电量查询（0x11 / 0x06）

```
发送：report 0x11，body = [0x06, 0x00 × 19]
接收：report 0x11，payload = XOR0xFF(raw[2:])
  payload[3] = 充电标志（0 未充电；1 充电中；实测充电时 firmware 可能回 0x45 等非常规值）
  payload[4] = 电量 %
  payload[9:]= 设备名（NUL 结尾，实测 "A7 Pro"）
```

- 鼠标休眠 / 关机时收不到 `0xE2` 就绪帧，读到的是无效数据
- 无效包特征：电量越界（0 或 >100）
- ⚠️ **绝对不要发 `F4 55` 载荷查询电量**——那是 profile 重载（配置档重载）命令，会让鼠标重载板载配置导致 DPI 变化（真机踩坑）

部分固件把回包走中断端点而非特征报告，需同时监听 `dev.read()`（0xE2 / 0x1D / 0x13 开头的短帧，`[3]`=充电、`[4]`=电量）。

## 3. 身份帧（0x11 通道同步读）

用 `HidD_GetFeature(0x11)` 可同步拿到身份帧，比等 0xE2 推送快：

```
raw[1..2]   VID（LE）
raw[3..4]   PID（LE）
raw[5..8]   固件版本（LE u32）
raw[9]      Bit0-2 连接形态（0 有线 / 1 2.4G / 2 蓝牙）+ Bit3 在线
raw[10]     电量 %
raw[11]     充电状态
```

## 4. 配置读（0x12 / 0x67）

```
发送：report 0x12，body = [0x67]
接收：report 0x12，63B payload：
  [0]      档位表
  [1]      USB：回报率（高 4 位）| 档位索引（低 4 位）
  [2]      2.4G：同构
  [4..15]  X 轴六档 DPI，u16LE
  [16]     档位掩码（bit i = 档位 i 启用；实测 0x06 = 档位 1、2 启用）
  [17]     传感器位域
  [18]     去抖 ms
  [19]     休眠分钟
  [51..62] Y 轴六档 DPI，u16LE
```

实测默认档位表：`400 / 800 / 1600 / 3200 / 6400 / 26000`。

**可信度校验（必做）**：
- 读得太快会拿到固件对主机请求的回显（XOR 后全零 = 0 档 0 DPI），全零包直接丢弃重试
- 每个 DPI 值必须在 `100..26000` 内，否则整包判废
- 读不到时用 `0x11` 短报文发 `[0x58, 0x00]`（profile select 0）唤醒长报文通道，睡 130ms 再试

## 5. 配置写（0x12 / 0x40）——⚠️ 与读帧不同构

```
发送：report 0x12，body（64B）：
  [0]      0x40（命令字）
  [1]      USB 档位索引（0~5，纯索引，高 4 位被固件忽略）
  [2]      2.4G 档位索引（0~5，同上）
  [3]      保留 0x00
  [4..15]  X 轴六档 DPI，u16LE（照抄读到的值）
  [16]     档位掩码（照抄读到的值）
  [17]     0xFF
  [18..29] Y 轴六档 DPI，u16LE（照抄读到的值）
  [30..63] 0x00
```

**⚠️ 最大坑**：直接拿读取帧（63B）改一个字节回写会**整表错位写坏**——实测 X 表变成
`26000 / 8193 / 16387`。FerrisPulse 里 A5 V2 用的 `0x57` + 回写读取帧的方式对 A7 Pro
**不适用**。写完必须睡 ~250ms 再读回校验：档位生效且 X/Y 表与写入值一致才算成功。

## 6. 回报率（0x11 / 0x41）

```
发送：report 0x11，body = [0x41, usbRateIdx, freeRateIdx]
索引 0..5 = 125 / 500 / 1000 / 2000 / 4000 / 8000 Hz
```

2.4G 连接下只更新 `[2]` 那一路（freeRate），USB 路不影响。

## 7. 记录与防抖策略（应用层）

2.4G 链路会偶发垃圾包，实测出现过 `83% → 6% → 83%` 的假读数。应用层的对策：

| 规则 | 说明 |
|---|---|
| 跳变 >10% 不采信 | 单次读数与上次差值超过 10 个百分点时丢弃，显示保留上次电量；连续两次读到同一值才承认（防误杀真实校准跳变） |
| 记录基准 = 最后一次记录值 | 存在 `history.json`，重启后接着算，不因重启丢档 |
| 变化 ≤5% 才落表 | 超过 5% 的大跨度（休眠后唤醒、插拔切换）确认两次后静默更新基准，不写脏数据 |
| 充电时 10 秒快轮询 | 检测到充电自动提频，拔线恢复用户设置 |
